# 设计思路：反刍打断（青少年版）

版本 v1.0 · 2026-11 · 交付形态：静态 H5（可直接"添加到主屏幕"当 App 用）

---

## 0. 一句话

**不劝孩子"别想了"，而是教他认出"我正在绕圈"，并给他一个 30 秒就能做的动作把圈打断。**

选题不是"青少年抑郁 App"，而是**反刍思维（rumination）**这一个可测量的中间过程。
理由：抑郁是结果、要诊断、要资质、要背责任；反刍是**过程**，是每个人自己当下就能察觉的东西，
而且它是少数"有证据能被短时干预改变"的认知环节。抓过程，产品才敢做得小、做得轻、做得不装专家。

## 1. 证据 → 产品决策（这张表是整个设计的承重墙）

| 研究结论 | 出处 | 变成了什么设计 |
|---|---|---|
| 反复思考负面情绪及其原因/后果、而不去解决问题，会延长并加重抑郁发作 | Nolen-Hoeksema 1991；Nolen-Hoeksema, Wisco & Lyubomirsky 2008 | 首页只问一件事："现在绕圈的强度 0–10"，把抽象概念变成一个可打分的身体感觉 |
| 反刍分两种：**忧思 brooding**（被动纠结、拿现状和标准比）与**反省 reflection**（主动分析、找办法）；前者有害、后者中性甚至有用 | Treynor, Gonzalez & Nolen-Hoeksema 2003 | 自评页不做单一总分，而是**两条分开画**；文案绝不写"想太多=有病"，避免让用户以为"我不该思考" |
| 青少年样本里，忧思与抑郁症状的关联比反省更稳定 | Burwell & Shirk 2007；Muris, Fokke & Kwik 2009；Rood 等 2009（非临床青少年元分析） | 目标用户定为 12–18 岁；所有卡片以"降忧思"为唯一目标，不承诺改善成绩或睡眠 |
| 针对过度担忧与反刍的**短程、结构化**干预能降低青少年与青年成人的焦虑抑郁风险 | Topper, Emmelkamp, Watkins & Ehring 2017（RCT, Behav Res Ther 90:123-136） | 陪练做成**固定 5 步**，不做开放聊天；一次只问一个问题，一轮 ≤ 5 分钟 |
| 反刍聚焦 CBT 的核心是把"为什么型/抽象"加工翻译成"怎么做型/具体"加工；缓解期青少年做 RFCBT 后行为激活水平上升 | Watkins 的 RFCBT 体系；Langenecker 等青少年 RFCBT 试验；Feldhaus 等 2020 | "把为什么换成下一步"这张卡 + 日志的**重复/可行动自动分流**，就是这个翻译动作的产品化 |
| 行为激活对抑郁有效（"先做，情绪跟在后面"） | Ekers 等 2014 元分析 | 首页"今天的一件小事"：只要求 5 分钟、能判断做完没，不要求心情好才做 |
| 用名字或第三人称跟自己说话，能制造心理距离、降低负面情绪，且不太消耗认知控制 | Ayduk & Kross 2010；Kross 等 2014；Moser 等 2017 | "换个机位"卡：强制把主语从"我"换成"她/他 + 名字"。成人实验室证据强，青少年证据在补，卡片里如实写明 |
| 短时、高频、手机交付的正念/打断练习在 13 岁上下样本里能降低反刍 | 针对 152 名青少年（平均 13.7 岁）的手机短时正念 RCT | 卡片时长全部设计成 **1–3 分钟**，而不是"每天 10 分钟冥想"；一天 3 次就算达标 |
| 一起反复讨论负面事件（共同反刍 co-rumination）在青少年中与更多内化症状相关，即使出于好意 | Rose 2002, Child Development | 家长/老师页把"陪他把同一件事分析到第三遍"明确列为**别做**，这是市面上家长建议里最常见的好心错误 |
| 中文 RRS 修订版信度良好（22 条目，α=0.91） | 韩秀、杨宏飞 2009，中国临床心理学杂志 17(5) | 自评条目直接用公开中文条目文本，不改写、不编造，避免"自创量表"的伪专业 |
| 青少年抑郁症状筛查阳性率 24.6%（重度 7.4%），随学段上升 | 中科院心理所《中国国民心理健康发展报告（2019—2020）》 | 用于说明"这不是个别现象"，同时**明确写"筛查阳性 ≠ 确诊"**，防止用户自我贴标签 |

一句话总结这张表的用法：**每一张卡片都能回答"凭什么是这样"。** 回答不了的（比如"5-4-3-2-1 着陆"）
在卡片"依据"里就只写"临床稳定化技术的常规做法"，不假装是 RCT 结论。

## 2. 用户与真实场景

主用户：13–18 岁在校学生。次用户：家长、班主任/心理老师（只给"怎么说话"，不给"怎么管理孩子"）。

场景不是"我想调节情绪"，而是这些具体时刻：

- 晚自习回宿舍躺下，白天被老师点名的那句话开始第 4 遍重播；
- 月考成绩出来，从"我考砸了"滑到"我就是不行"，中间只用了 20 秒；
- 发出去的消息没被回，开始把三个月前的事一起翻出来；
- 周末在家，爸妈一句"我们为你付出这么多"，之后一整个下午坐在原位没动。

由此推出四条硬约束：

1. **手机可能是共享的**（家长随时会拿去看）→ 首页不能一眼看出"孩子在想什么"，标题中性、内容不在列表页展开、默认不联网。
2. **不能让他觉得自己是病人** → 全站不出现"症状/治疗/患者/疗程"，用"绕圈/打断/这一步"。
3. **使用时点是情绪最差的那 30 秒** → 打开到能用的动作不超过 2 次点击，卡片第一屏就是步骤，不是介绍。
4. **写不出漂亮话** → 所有输入框都允许一句话、允许脏、允许前后矛盾，并明说"照原样写"。

## 3. 定位与"不做什么"（比做什么更重要）

| 不做 | 原因 |
|---|---|
| 不诊断、不筛查出"抑郁症" | 非医疗机构不得开展心理治疗（《精神卫生法》）；`safety` 判定只做"是否要给求助入口"，不做疾病判断 |
| 不做开放域 AI 陪伴 | 一个会顺着孩子话往下说的语言模型，是反刍的放大器（可以陪他绕一整晚）。v1 用**本地固定 5 步脚本**，明确标注"不是 AI、不理解你" |
| 不做社区、不做树洞广场 | 青少年同伴广场上的负面互相强化，正是 co-rumination |
| 不做打卡排行、连续天数、勋章 | 断签会制造新的自责；进度只呈现趋势，不做道德评价 |
| 不做"通知家长/老师" | 危机响应必须是真人判断，工具不能替孩子决定谁会被告知 |
| 不做用药建议 | 一律指向开药的医生 |

## 4. 核心机制：察觉 → 打断 → 转向

```
        ┌──────────── 察觉（30 秒）────────────┐
        │  温度计 0–10 + 触发标签 + 那句原话    │
        └───────────────┬──────────────────────┘
                        │ 词表规则自动分流
              ┌─────────┴─────────┐
        在重复 ↻                 可行动 →
              │                    │
   ┌──────────┴──────────┐         │
   │ 打断（1–3 分钟）    │         │
   │ 8 张卡，按强度推荐  │         │
   │ 做之前/做之后打分   │         │
   └──────────┬──────────┘         │
              └───────┬────────────┘
                转向（3 分钟）
        "为什么" 翻译成 "一个动词 + 一个时间点"
              + 今天一件 5 分钟小事
                      │
                记录页看两周趋势
```

三个设计上的坚持：

- **察觉先于内容**。先让他给强度打分，再让他写字。顺序反过来，写字本身就会变成新一轮反刍。
- **打断不要求"想通"**。卡片只要求做完一个动作，然后回到 0–10 打分。降 1 分也算数——这条写在按钮下面，防止他因为没"根治"而自责。
- **转向必须具体**。"把数学提上去"会被规则判成不合格（缺时间点/动词），陪练会直接说"这句还是太大"。这是整个产品里唯一"不温柔"的地方，因为温柔在这里没用。

强度决定卡片：`≥8` 只推**不用写字**的（着陆、呼吸）；`6–7` 推呼吸/身体先动；`4–5` 推换地方/占注意力；`<4` 直接推"下一步"翻译卡。
逻辑写在 `engine.js: suggest()`，一眼能看懂，不做黑盒推荐。

## 5. 信息架构

```
底部 5 个 tab（小程序式）
├─ 今天   /today     温度计 · 触发标签 · 原话分流 · 推荐卡 · 今日小事 · 两周趋势
├─ 打断   /break     8 张卡列表 + 何时用哪张的对照表
│         └ /card/:id  单卡：为什么 / 步骤 / 计时器或填空 / 前后打分 / 依据
├─ 记录   /journal   写一条 → 自动分类（命中词可见，可手动改）· 表达性书写 4 天 · 趋势图
├─ 自评   /scale     反刍风格自评 10 题（忧思 5 / 反省 5）· 双条对比 · 出处与免责
└─ 我的   /more      数据概览 · 求助 · 家长老师 · 数据与隐私 · 来源与局限
          ├ /help      12356 · 打不通时的替代路径 · 何时该找专业帮助
          ├ /parents   先别说这三句 / 有用的动作 / 信号
          ├ /privacy   本地说明 · 导出 JSON · 导入 · 立即清空
          ├ /sources   16 条文献与官方来源 + 词表公开 + 做不到什么
          └ /talk      本地 5 步陪练（从"今天"和"记录"页都能进）
```

页面跳转规则：**任何页面顶部右侧常驻"求助"**，危机入口不藏在三级页面里；
所有路由用 hash（`#/journal`），因此 GitHub Pages 的子路径 `/repo/` 下不需要任何服务器重写。

## 6. 视觉与交互规范

- **画布**：`max-width: 520px` 居中，`100dvh` 弹性高度，`env(safe-area-inset-*)` 处理刘海与底部横条；
  在桌面浏览器里表现为一部手机，在手机上就是全屏 App。
- **配色**：暖纸白底 `#F6F2EC` + 墨绿主色 `#3B6B5E` + 陶土强调 `#C6613F` + 危机红 `#B0453C`。
  刻意避开两种常见错误：医院蓝（像挂号 App）和糖果色（像儿童玩具，14 岁会拒绝）。
  `prefers-color-scheme: dark` 有整套变量覆盖，晚自习熄灯后不刺眼。
- **字号**：正文 16px/1.6，卡片标题 15px，说明文字 12.8px，来源脚注 11.8px。最小不低于 11.5px（再小在手机上读不动）。
- **微交互**：滑杆实时改文案（不用点确认）；卡片按压缩放 0.985；toast 1.9 秒自动消失；
  呼吸练习用一个 CSS 圆做 4s 放大 / 6s 缩小，**跟着圈走**是它唯一的指令。
- **图表**：内联 SVG，无图表库。折线=每日强度均值，柱子=每日打断次数，虚线在 5 分处（"在绕"的分界）。
- **零外部依赖**：没有 CDN、没有字体、没有统计脚本、没有图片外链。断网也能完整使用。

## 7. 文案规范（写代码前先定）

| 场景 | 用 | 不用 |
|---|---|---|
| 描述状态 | "在绕圈""脑子被占住" | 反刍症状、病理性思维 |
| 描述工具 | "打断""这一步""练一次" | 治疗、疗程、干预方案 |
| 描述分数 | "偏能收得住""绕圈占主导" | 轻度/中度/重度抑郁 |
| 对用户 | "你"，不叫"同学""宝""亲" | 任何昵称 |
| 对失败 | "降 1 分也算""写了更难受就停，这不算失败" | "加油，你可以的" |
| 对求助 | "这不是靠想通能过去的，需要人来搭一段" | "建议寻求专业帮助" |

全站禁用词：`治愈 / 根治 / 疗效 / 患者 / 病症 / 抑郁症 / 焦虑症 / 一定要坚强`。
（自评页出现"抑郁"二字仅限于引用量表条目原文与文献名，且紧跟"这不是诊断"。）

## 8. 数据模型与算法

存储：`localStorage["fanzhua.v1"]`，单键 JSON，无第三方。

```jsonc
{
  "checks":    [{ "ts": 0, "day": "2026-11-19", "level": 7, "trigger": "考试/成绩", "note": "", "kind": "repeat" }],
  "breaks":    [{ "ts": 0, "cardId": "land", "before": 7, "after": 5 }],
  "journal":   [{ "ts": 0, "text": "", "kind": "repeat|action|mixed|unknown", "why": "", "words": [] }],
  "actions":   [{ "id": 0, "day": "", "kind": "愉悦|成就|自己写的", "t": "", "done": false, "doneTs": 0 }],
  "writing":   [{ "day": 1, "title": "", "text": "", "ts": 0 }],
  "scale":     { "ts": 0, "answers": {}, "brood": 0, "reflect": 0, "total": 0 },
  "coach":     [{ "role": "me|them|sys", "text": "" }],
  "coachState":{ "node": "s1", "done": false },
  "worry":     { "time": "19:30", "list": "" },
  "nextCard":  { "fixed": "", "mine": "", "act": "" }
}
```

**唯一的"算法"是词表分流**（`engine.js: classify()`）：字符串包含匹配，命中词原样显示给用户，
四类结果 `repeat / action / mixed / unknown`，全部可手动改。刻意不做语义模型——
可解释、可被用户当场推翻，比"聪明"重要。词表在来源页全文公开。

趋势指标：

- 两周平均强度 = 每日 `checks.level` 均值的均值（缺日不计入，不做插值）；
- 每次平均降幅 = `mean(before - after)`，只统计打了分的打断；
- 达标线：一天 3 次打断 = 比昨天好，5 次以内都算正常（写在进度条下面，防止他冲 KPI）。

## 9. 危机路由（三层，且不上报）

1. **词表命中**（`crisisWords`，13 个词，公开在来源页）：在任何输入框出现时——
   - 今天页：不推荐工具卡，直接换成求助卡；
   - 记录页：保存前先给求助卡；
   - 陪练页：**立刻停止流程**，只输出求助入口，不接着问。
2. **求助卡内容**：全国统一的 **12356** 心理援助热线（`tel:` 链接，点一下就拨）、120/110、
   "先发给一个活的成年人"的具体话术、把危险物品放远、以及"要专业帮助不丢人"。
3. **不做的事**：不自动通知家长或老师、不上传、不外呼。危机响应必须由真人决定，
   工具的責任是把路铺到最近的那个真人脚下。

设计上的取舍：命中词表是**过敏感**的（宁可多推一次求助卡），因为漏报的代价不可逆，
而误报只是多看了一眼红色卡片。

## 11. 怎么验证它有用（小样本，别装大研究）

- **北极星**：每周完成"打断 + 前后打分"的次数（不是打开次数）。
- **护栏**：① 求助入口被点击的次数（太低=危机词表太钝，太高=文案在制造恐慌）；
  ② 7 天后仍在用的比例；③ 自评忧思分前后差（第 1 天与第 14 天各测一次）。
- **两周试点怎么做**：10–20 人，不发"打卡奖励"，只在第 1 天/第 14 天各做一次自评；
  结束时问三个问题：哪张卡真的用过、哪一次打断了、有没有哪句话让他更难受。
- **判定线**：如果两周里没人用过任何一张卡片，说明问题在入口（不会有人主动打开一个"反刍"App），
  而不是内容——那时该改的是分发场景（心理课前 3 分钟、班会投屏），不是加功能。

## 12. 已知局限（写在这里，不藏在心里）

1. 自我调节工具对**已经重度抑郁**的青少年几乎无效，依从性会崩；它服务的是"还在上课但晚上停不下来"的那一段。
2. 卡片把有证据的干预路线压缩成 3 分钟动作，**不等于**等效于 8 次正式 RFCBT。
3. 词表分流会误判（反讽、方言、写一半），所以必须允许手动改。
4. 没有真人兜底；12356 是公共热线，不是本产品的一部分，接通质量不由我们控制。
5. 短时自评受当晚状态影响大，趋势比单点可信。
6. 文献以英文与大陆期刊为主，样本多为西方/大学生；青少年本土证据仍在积累，卡片里凡属外推都标了"青少年证据仍在补"。

## 13. 从 H5 到微信小程序：迁移说明

你最初说的是"小程序"。这一版做成 H5 部署在 GitHub Pages，是**故意的**，原因有三条现实的：

| 障碍 | 说明 | 结论 |
|---|---|---|
| 类目与主体资质 | 微信里心理/健康相关内容通常要走"医疗"相关类目，需要企业或机构主体与资质材料；个人主体基本走不通 | 想上小程序，得借学校/机构的主体，不是技术问题 |
| 审核与措辞 | 小程序审核对"抑郁""治疗""心理咨询"等词敏感，本站文案要重写才能过 | 现在这版文案（"绕圈""打断"）本来就为这个场景准备 |
| 迭代速度 | 静态站改一次 push 就上线；小程序每次改动走审核 | 试点期用 H5，验证完再搬 |

**能直接搬的**：页面树 → 小程序 `tabBar` + 5 个页面；卡片列表/详情 → 分包页面；
**要改的**：`localStorage` → `wx.setStorage`；`tel:` 链接 → `wx.makePhoneCall`；
内联 SVG 图表 → `<canvas>` 或 `cover-view`；hash 路由 → `wx.navigateTo`；
**必须新增的**：首次进入的年龄确认与隐私说明屏（小程序强制要求）。
数据模型和 `engine.js` 的纯函数（`classify` / `suggest` / `coachStep`）可以原样复用。

## 14. 目录结构

```
fanzhua-mini/
├─ index.html                 单页外壳 + tabbar（hash 路由，无需服务器重写）
├─ manifest.json              添加到主屏幕
├─ .nojekyll                  关 Jekyll，纯静态
├─ assets/css/app.css         设计变量 + 组件（含暗色）
├─ assets/js/config.js        后端开关（默认空）
├─ assets/js/data.js          内容层：8 张卡、10 题、词表、来源 —— 改文案只动这里
├─ assets/js/engine.js        逻辑层：分流 / 危机 / 建议 / 陪练状态机（纯函数，可单测）
├─ assets/js/app.js           视图层：路由、表单、计时、图表、导入导出
├─ assets/icon/               SVG 图标 + 512 PNG（主屏用）
├─ docs/DESIGN.md             本文
├─ docs/BACKEND-ALIYUN.md     阿里云方案与合规清单
└─ aliyun-fc/chat.js          FC 函数示例代码（未部署）
```

内容层 / 逻辑层 / 视图层分开，是为了让**改一句话不用碰代码**：
卡片文案、量表条目、词表、来源全在 `data.js`，非技术协作者也能维护。
