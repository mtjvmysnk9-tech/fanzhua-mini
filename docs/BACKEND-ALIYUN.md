# 阿里云后端方案（设计 + 接口契约 + 上线代价）

> 状态：**这份方案是设计稿，还没有部署，也没有调用任何真实服务。**
> 站点默认是纯本地的：`assets/js/config.js` 里 `apiBase` 为空、`allowUpload: false`，
> 页面不会发出任何请求。下面的东西只有在你自己开通阿里云、部署函数之后才会生效。

---

## 1. 先划边界：什么东西可以出设备

这个产品的核心内容（反刍的具体句子）是一个孩子最不愿意被别人看到的部分。
所以默认原则是：**内容不出设备，只有"能力"按需出设备。**

| 数据 | 默认存放 | 是否允许上传 | 理由 |
|---|---|---|---|
| 反刍日志原文、书写正文 | localStorage | **否** | 一旦上云就是敏感个人信息，且没有收益能覆盖风险 |
| 打卡强度 0–10、打断次数、卡片 id | localStorage | 可选（匿名聚合） | 只有趋势对研究和迭代有用，句子本身没用 |
| 量表得分（忧思/反省） | localStorage | 可选（匿名聚合） | 同上 |
| 陪练对话 | 本地预设脚本 | **默认否** | 接后端才变成真对话，且必须逐条明示 |
| 危机词命中 | 本地，不上传 | **否**（除用户主动求助） | 自动上报会让孩子不敢写；只在用户自己点"我需要帮助"时留一条审计记录 |

设备标识：前端 `crypto.getRandomValues` 生成 16 字节随机 id，存本地，可随时"重开"重置。
**不采集**姓名、学校、班级、手机号、位置、通讯录、剪贴板。

## 2. 服务选型（阿里云）

```
浏览器（GitHub Pages 静态站）
        │  HTTPS，CORS 精确白名单
        ▼
函数计算 FC 3.0（Web 函数，Node.js 20 运行时）
        ├── 百炼 DashScope · 通义千问（OpenAI 兼容模式）  → 真对话
        ├── 内容安全（文本审核增强版）                     → 输入/输出双向过滤
        ├── 表格存储 Tablestore                            → 匿名事件，TTL 90 天
        ├── 日志服务 SLS                                   → 访问日志，只留元数据
        └── 密钥：FC 环境变量 / KMS 凭据，绝不下发到前端
```

为什么这样选：

- **FC 而不是 ECS**：用量极低且不可预测（一个班、几个学生），按量计费 + 冷启动可以接受；不用维护机器。
- **Tablestore 而不是 RDS**：只需要 `deviceId + 时间 + 事件类型 + 数值` 的宽表和时间序，Serverless 存储不需要预留实例，能设 TTL 自动过期。
- **API 网关可选**：FC 的默认测试域名（`*.fcapp.run`）不能用于正式对外，且有 QPS 与稳定性限制；正式用要么绑自定义域名（需备案），要么挂 API 网关做限流与配额。
- **百炼**：模型侧只需要一个短上下文对话，`qwen-plus`/`qwen-turbo` 足够；不需要向量库、不需要 Agent。

## 3. 接口契约

Base：`https://<你的域名>/v1`（前端写在 `assets/js/config.js` 的 `apiBase`）

### 3.1 `POST /v1/chat`

请求：

```json
{
  "deviceId": "3f9c…（随机，无含义）",
  "stage": "s2",                       // 前端流程节点，用来约束模型别抢跑
  "messages": [
    { "role": "user", "content": "今天数学小测最后一题没写完，我一直在想" }
  ],
  "signature": "HMAC-SHA256(deviceSecret, body+ts)",
  "ts": 1763500000000
}
```

响应：

```json
{
  "reply": "这题没写完，最让你过不去的是哪一句？",
  "suggestions": ["换成“他/她”重述一遍", "写一个今晚能做的最小动作"],
  "safety": { "level": "low", "action": "continue" },
  "model": "qwen-plus",
  "serverTs": 1763500001234
}
```

`safety.action` 只允许三个值：`continue` / `deescalate`（给着陆卡）/ `route_help`（返回求助卡，**此时 `reply` 必须是固定文案，不能是模型生成的**）。

### 3.2 `POST /v1/events/batch`

匿名事件批量上报，只接受白名单字段：

```json
{
  "deviceId": "3f9c…",
  "events": [
    { "type": "checkin", "day": "2026-11-18", "level": 7 },
    { "type": "break",   "day": "2026-11-18", "card": "land", "before": 7, "after": 5 },
    { "type": "scale",   "day": "2026-11-18", "brood": 16, "reflect": 9 }
  ]
}
```

服务端**丢弃任何未知字段**，且表结构里没有 `text` 列——从设计上不给"顺手把原话传上来"留通道。

### 3.3 `GET /v1/report?deviceId=…`

返回服务端算好的周报（可选功能，前端本地也能算，所以优先级最低）。

### 3.4 `POST /v1/sos/ack`

用户主动点了"我现在需要帮助"。只记录 `deviceId + 时间 + 城市级粗粒度（可选）`，返回本地热线与就近资源文案。**不含自动外呼、不含通知家长**——这两件事必须由真人决定。

### 3.5 通用约定

- 全部 `application/json; charset=utf-8`，HTTPS only。
- CORS：`Allow-Origin` 精确匹配（`https://<user>.github.io`），带 `Allow-Credentials: false`。
- 鉴权：设备首次使用生成 `deviceSecret`（本地保存），请求带 HMAC + `ts`，服务端 ±120 秒外拒绝，防重放。
- 限流：单设备 10 次/分钟、30 次/天；超限 `429 { retryAfter }`，前端自动回落到本地脚本并提示"后端太忙，先用本地流程"。
- 错误：`400 BAD_BODY` / `401 SIGNATURE` / `429 RATE` / `502 MODEL` / `500 INTERNAL`。任何非 2xx 都不阻塞核心功能。

## 4. 模型侧硬约束

System prompt（服务端拼装，前端传不进来的部分）：

```
你是给 12–18 岁中国学生使用的"反刍打断"练习陪练，不是医生、不是治疗师、不是朋友。
1. 不做任何诊断，不提诊断名词（抑郁症/焦虑症），不说"你这是病"。
2. 不建议停药、不建议任何药物剂量，遇到用药问题一律指向开药的医生。
3. 不承诺保密，不要求对方"别告诉家长老师"；始终推动他找一个现实中的成年人。
4. 每次回复 ≤ 60 个汉字，最多一个问题，语气平实，不用感叹号，不用"亲""宝"。
5. 只推进当前 stage 的任务，不要跳到建议，除非对方已经给出可行动的句子。
6. 出现自杀/自伤相关内容时不再展开对话，只输出一句"需要现在找个人陪你"，由服务端替换成求助卡。
7. 不编造研究、数据、热线号码；不确定就不说。
```

服务端在模型返回后再做一次：输出内容安全审核 → 危机词二次检查 → 长度与禁用词过滤 → 才落到日志。

## 5. 合规清单（照这个逐条对）

- 《个人信息保护法》：情绪与健康信息属于**敏感个人信息**（第 28 条），处理需单独同意；**不满 14 周岁需监护人同意**并制定专门处理规则（第 31 条）。→ 站方需要在首次进入时加一屏"同意 + 年龄确认"（当前静态版没做，接后端前必须做）。
- 《未成年人网络保护条例》（2024-01-01 施行）：防沉迷、个人信息保护、投诉渠道；面向未成年人的产品有更高注意义务。
- 《精神卫生法》：非医疗机构不得开展心理治疗。→ 全部文案统一"自我调节练习/教育性工具"，不写"治疗""疗程""治愈"。
- 生成式 AI：对外提供生成式服务需履行备案/登记与安全评估义务，正式上线前查清当时属地网信要求。
- 域名：中国内地访问的自定义域名需要 **ICP 备案**（阿里云流程约 1–2 周）；不备案只能用 FC 测试域名，随时可能被限。
- 日志：访问日志保留期与内容审计分别设置（建议事件 90 天、审计 180 天），到期自动删除；提供"抹掉某设备"的运维脚本。

## 6. 成本与代价（先算账再决定要不要做）

以"一个班/几十人、每人每天 ≤ 10 次请求"这种量级估：

| 项 | 量级 | 备注 |
|---|---|---|
| FC 调用 | 几元/月 | 按量计费，几十万次以内基本都在个位数；有免费额度 |
| Tablestore | 0–20 元/月 | 按量模式，几乎可忽略；预留实例反而贵 |
| SLS 日志 | 0–10 元/月 | 只留元数据、控制保留期 |
| 百炼 token | 主要成本 | 每次对话 1–2k token，价格随模型与活动变化，**以控制台价格页为准**，别按本文估的数签合同 |
| 域名 + 备案 | 域名几十元/年，备案免费但耗时 | 备案要 1–2 周，需要身份证与主体信息 |
| 内容安全 | 按调用量 | 如果只做一个"是否危机词"的门，用词表在 FC 里本地判断即可，**不一定要花钱** |

**结论：真金白银的成本主要在 token 和你的时间，而不是基础设施。**
所以推荐顺序是：

1. 先把静态站发出去（零成本，可立刻给人用）；
2. 校园/班级里跑两周，看本地模式有没有人真的用；
3. 有人用且明确需要"真对话"，再开 FC + 百炼；这时才涉及同意页、备案、审计这一整套。

第 3 步不做，这个产品仍然成立——它最有价值的部分（察觉、打断、翻译成动作）本来就设计成离线可用的。

## 7. 部署动作（按零命令行的人来写）

代码已经放在 `aliyun-fc/chat.js`（单文件，无第三方依赖，Node.js 20 运行时用 `fetch`）。

1. 阿里云控制台 → 函数计算 FC → 创建函数 → 选"Web 函数" → 运行时 **Node.js 20** → 代码上传方式选"在线编辑"。
2. 把 `aliyun-fc/chat.js` 的内容整段粘进 `index.js`，点"部署"。
3. 同一页"配置 → 环境变量"里加：
   `DASHSCOPE_API_KEY`（百炼控制台创建，只显示一次，复制后存好）、
   `ALLOW_ORIGIN=https://<你的用户名>.github.io`、
   `DEV_SECRET_PEPPER=<你自己乱敲 32 个字符>`。
4. "测试函数"页里用 `POST /v1/chat` 的样例 body 跑一次，看到返回 JSON 才算通。
5. 把函数给的公网地址填进 `assets/js/config.js` 的 `apiBase`，本地先测，再 push 更新 GitHub Pages。

正式对外前还需要：绑定已备案域名（或用 API 网关），把 `allowUpload` 打开之前补同意页。

## 8. 降级与失效

- 后端不可用/超时 → 前端立刻回落本地预设流程，功能不断（`config.js` 的 `timeoutMs` 控制等待）。
- 模型返回不合规 → 服务端过滤后返回固定兜底句，并记一条 `502 MODEL` 供你排查。
- 配额耗尽 → 前端显示"今天用完了，明天再来"，同时把这一轮内容留在本地不落网。
- 任何情况下，求助入口（12356）不依赖后端存在，纯静态渲染。
